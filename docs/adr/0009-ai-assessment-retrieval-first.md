# ADR-0009：AI 保研评估采用“检索增强优先”，不默认训练自有大模型

- 状态：Proposed
- 日期：2026-09-20

## 背景

AI 保研评估需要根据用户背景、目标院校、院校/项目信息与真实保研案例输出个性化建议。

外部原型展示了“背景录入 → 目标院校 → 评估结果”的用户体验，但其内部为固定权重和静态规则，不适合作为生产智能逻辑。

## Proposed 决策

V1 不把“训练一个大模型”作为前置条件。

优先采用：

```text
用户结构化资料
  -> 服务端校验/标准化
  -> 检索院校/项目规则
  -> 检索相似真实案例
  -> 构建证据上下文
  -> 调用可替换的大模型 API
  -> 结构化 JSON 输出
  -> Schema / 业务规则校验
  -> 保存证据、模型、Prompt、数据版本
  -> 返回小程序
```

这是 RAG/检索增强式业务 Agent，而不是先微调/训练基础模型。

## 为什么 V1 不先训练

- 九辰当前自有真实案例量不足以支撑高质量监督训练；
- 外部案例存在来源、授权、口径差异，不能直接当训练集；
- 保研政策、院校要求和案例会持续变化，检索数据比固化到模型参数更易更新；
- API 模型可以快速验证产品价值；
- 后续若积累大量高质量、授权、结构化九辰数据，再评估微调或专用模型。

## AI 服务边界

建议 API 内保持一个独立逻辑模块：
- Assessment Orchestrator；
- Model Provider Adapter；
- Case/School Retriever；
- Prompt/Agent Version；
- Output Schema Validator；
- Evidence Recorder。

仍然保持单体服务，不因 AI 就拆微服务。

## 输出建议

V1 评估结果至少包含：
- 学生背景摘要；
- 优势；
- 风险/短板；
- 目标院校逐校分析；
- 冲刺/匹配/保守建议（定性）；
- 推荐行动计划；
- 相似案例；
- 证据引用/数据来源；
- 不确定性或资料缺口。

禁止模型凭空给出精确录取概率。

## 何时再考虑训练/微调

只有同时满足以下条件后再评估：
- 九辰积累足够数量的自有授权案例；
- 输入/输出 Schema 已长期稳定；
- 已建立人工高质量标签；
- API/RAG 方案出现可量化瓶颈；
- 微调收益能通过离线评测证明。

在此之前，训练自有大模型不是 V1 依赖。
