# ADR-0004：分阶段部署与微信版本发布

- 状态：Accepted
- 日期：2026-09-17

## 背景

微信公众平台开发侧已经准备，小程序后续同时涉及两条发布链路：微信端代码版本，以及 API/数据库服务端环境。若等所有功能完成后才第一次部署服务器，会把合法域名、HTTPS、微信登录、真机网络、支付回调等风险集中到项目末期。

## 决策

采用“本地优先开发 + 尽早建立 staging + 最后 production”的分阶段流程，而不是开发结束后一次性上传服务器。

### 小程序端

```text
本地开发
  -> 微信开发者工具模拟器
  -> 真机预览/调试
  -> 上传微信体验版
  -> 测试验收
  -> 提交审核
  -> 正式发布
```

### 服务端

```text
本地 API/数据库开发
  -> 最小链路跑通
  -> staging 测试服务器
  -> 配置 HTTPS / 合法域名
  -> 小程序真机联调
  -> production 正式服务器
```

## 阶段边界

### P0

只做文档、架构和约束，不部署业务服务。

### P1

完成最小小程序、API、数据库和认证骨架后，建立 staging。此时即可开始真实微信网络环境联调。

### P4/P5

AI 与支付分别在 staging 完成真实闭环验证后，才允许进入 production。

## 微信公众平台配置原则

- 小程序代码上传密钥属于 Secret，不进入 Git；
- AppSecret、支付密钥、证书等只保存在受控环境；
- 合法域名指向 staging/production 的 HTTPS 服务；
- IP 白名单在服务器出口 IP 确定后再配置，避免现在填入临时开发网络；
- 生产配置与测试配置分离。

## 结果

这种方式兼顾两点：

1. 前期仍可快速在本地施工，不需要天天操作生产服务器；
2. 微信平台相关风险不会积压到最后一周才发现。
