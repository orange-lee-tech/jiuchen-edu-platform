# 外部提供原型源码审计（2026-09-20）

## 1. 来源与定位

九辰教育提供了一份单文件 HTML/CSS/JavaScript 可交互原型，页面标题为“九辰保研 · 小程序 UI 原型 v0.1”。

该文件对本项目的权威性定义为：

- **产品/交互参考：高**；
- **字段与信息层级参考：高**；
- **生产技术架构参考：低**；
- **后端、数据库、安全、权限实现参考：不适用**。

原因：文件是浏览器内运行的演示原型，不包含真实 API、数据库、服务端鉴权、支付回调或 AI 模型调用。

## 2. 从原型确认的产品拓扑

原型确认的核心版图包括：

- 首页；
- 规划定位；
- 院校库；
- 保研学堂；
- 资讯库；
- 我的。

主要子能力：

- AI/定位三步流程：背景录入 → 目标院校 → 结果；
- 院校搜索与筛选；
- 课程展示和课程详情；
- “我的课堂”15 阶段时间轴；
- 绩点、英语、竞赛、科研、实习规划；
- 辅导老师与辅导记录；
- 资讯分类/筛选；
- 个人资料、订单、反馈、咨询；
- AI 评估次数/充值的用户体验入口。

这些内容应作为我们检查功能覆盖面的参考地图。

## 3. 不应直接复制的实现

### 3.1 AI 评分

原型内部仍使用固定学生画像、固定院校要求以及人工权重计算匹配分。

生产版不沿用：
- 固定前端评分常量；
- 固定院校门槛常量；
- 前端计算录取/匹配分；
- 看似精确但缺少证据链的百分比。

生产版继续采用当前 V1 基线：
- 服务端结构化输入；
- 检索真实院校/项目/案例；
- AI Agent 分析；
- 结构化 JSON；
- Schema 校验；
- 引用/证据记录；
- 不确定性表达。

### 3.2 评估次数和充值

原型的评估次数、套餐和充值记录都是浏览器内变量。

生产版必须由：
- CreditAccount；
- CreditLedger；
- Payment；
- 微信支付回调；
- 幂等处理

共同实现，客户端不能自行增减额度。

### 3.3 课堂数据

原型将 PLANS / PAPER / RECORDS / INTERN 等大量内容写在 JavaScript 常量中。

生产版必须数据驱动：
- Student；
- AcademicStage；
- Plan；
- CourseTarget；
- Mentor；
- CoachingRecord；
- StudentTeacherAssignment。

### 3.4 院校与课程

原型中的院校、课程、导师、案例数据适合帮助理解 UI 密度，不自动视为生产事实数据。

生产数据必须明确来源、更新时间、公开状态和维护责任。

## 4. 与当前项目基线的差异

### 已经主动纠偏
- 原型固定五维评分 → 当前设计为 AI Agent；
- 原型课程可表现价格 → V1 只展示/咨询，不做课程购买；
- 原型前端充值模拟 → 当前规划为服务端额度账本 + 微信支付；
- 原型静态课堂 → 当前设计为数据驱动阶段规则；
- 原型普通/VIP/VIP学员身份 → 当前设计为统一登录 + 游客 + 内部ID业务身份。

### 仍需补齐
- 院校库真实数据；
- 课程/师资真实数据；
- 资讯完整筛选；
- AI 三步评估实际闭环；
- 相似案例检索；
- 评估历史；
- 咨询与反馈真实数据流；
- 课程介绍 PDF/资料管理；
- 更完整的个人中心功能。

## 5. 使用方式

后续实现任何页面时：

1. 先看 V1 产品基线；
2. 再看本审计中的产品拓扑；
3. 需要视觉/字段细节时参考外部 HTML 原型；
4. 若原型实现与项目宪法、安全或已确认业务规则冲突，以项目治理文档为准；
5. 不直接复制原型中的硬编码业务数据和模拟逻辑。
