# AI 评估个人规划与历史报告上下文合同（2026-10-10）

状态：**GitHub 实装 / 未发布生产 / 真机 NOT RUN**。分支 `p1/foundation`。本功能补充既有 Assessment v1，不改变 provider `qwen3.8-flash`、六章节输出及付款规则。

## 客户端显示与存储
- 新评估与无该字段的老草稿默认 `includePlanning=true`、`includeRecentAssessments=true`，每项可独立关闭。
- `assessmentInputSchema.contextOptions` 只接受两项可选布尔。草稿保存的是选择权，不是材料副本或其他学员账号。
- 仅本人可打开评估；教师/员工/管理员不获运行权限。编辑过草稿后须在后台 `run` 时重新核对五项个人资料。

## 服务端读取边界
- 账号来源是已经鉴权的 Assessment 记录 `userId`，绝不接受客户端 userId/studentId。
- 规划：先以 `students.user_id` 找本人学员 ID，再按该 ID 查询 `student_plans`、`plan_revisions`、`plan_items` 与 `schedule_imports`。相同阶段/类型下，最新 `pending` 版本覆盖已审核版用于分析，但必须标记「学员待审核版」；仅取真实填写计划项，空项/未知状态/异常课表结构不会创造任务数据。
- 历史：`assessments.user_id` 强制归属、`status=succeeded`、排除当前正在运行的 ID、按 `completed_at` 降序，最多三条。仅提炼概况、各最多两条优势/风险/行动，重复文本去重，不把过去结论当作当前事实。
- 提取时硬限制原始记录数量与摘要长度；服务端不把完整课表 JSON、个人完整历史报告、商户资料或模型密钥塞到 Prompt。
- 没有学员身份/无真实记录 → 不生成这类证据。请求的数据表缺失或查询异常 → 不悄悄假装“已参考”，按现有后台失败与额度预留释放逻辑处理；生产 schema 需提前只读验证。

## AI 证据约束
- 压缩后的规划和历史分别成为 `account:planning`、`account:history`，标注为 internal/other；仅用于评估本人进度与建议，不充当任何学校官方来源。
- 证据片段和知识版本哈希随最终报告落库，用于追查本轮参考了哪些摘要。已有报告重新查看不触发评估。
- 不得把学员计划/历史摘录中的恶意指令当系统提示。无当年目标学校官网/官方招生要求的引用，目标分档仍应降级 insufficient_data；不得推导精确录取概率。
- 新增 `HistoricalMoeSchoolSource`：将小程序已收录的 116 条 985/211 历史建设名单生成为服务端轻量静态镜像，按学校中文名称精确匹配目标。每次返回带教育部历史 URL 和 2005/2006 年份的证据；固定 `kind=other`，不会满足模型输出「有学校/项目/案例实证支持」的硬门槛，故**不得仅凭学校名录作出冲刺/匹配/稳妥判断**。业内 C9、华五、五院四系等分类仅作用户筛选，未经另行核实不能作为官方项目证据。
- 生成器：`node tools/testing/generate-school-directory.cjs`；API 测试自动执行 `--check`，确保代码生成快照与小程序母表一致。运行时只加载编译后的 116 条小型事实数据，无爬虫、持久连接或新的后台常驻进程。
- 仍未接入当年官方招生专业、项目、夏令营推免细则及全量非 211 高校；下轮应建设可审计的来源/更新时间/学校 ID 目录，而不是复制未经验证的校方通知。
