# 产品优化候选 / Optimization Backlog

本文件只记录值得讨论的优化，不自动改变 V1 基线。每一项在正式实施前都需要产品确认。

## 使用规则

每项建议至少记录：

- 当前问题；
- 建议方向；
- 对 V1 的影响；
- 是否必须现在解决；
- 最终决策。

## 当前候选

### O-001 AI 评估展示方式

**问题**：原型使用固定五维权重和评分，容易让结果显得机械且产生虚假的精确感。

**方向**：V1 已确认改为 AI 结构化分析，重点展示依据、匹配理由、风险和案例证据，而不是固定权重总分。

**状态**：已部分纳入 V1 基线；具体 UI 待 AI 输出 Schema 确定后设计。

### O-002 首页信息密度

**问题**：原型首页同时承载较多入口、课程和资讯，移动端可能存在注意力竞争。

**方向**：V1 先忠实实现；真机测试后根据点击路径、滚动长度和首屏可读性决定是否收敛。

**状态**：V1 不主动重排。

### O-003 案例筛选

**问题**：案例数量增长后，单一列表可能难以定位相似背景。

**方向**：未来考虑本科层次、专业、排名、英语、科研/竞赛背景、录取院校等组合筛选。

**状态**：V1 非阻塞。

### O-004 资讯功能

**问题**：原型存在资讯模块，但收藏、分享、报名等能力是否必要尚未确认。

**方向**：V1 先保证资讯浏览和基本跳转；需要时再增加收藏/报名。

**状态**：V1 非阻塞。

### O-005 课程营销能力

**问题**：原型可扩展试听、优惠券、拼团等功能，但当前业务不要求课程在线支付。

**方向**：V1 保持“展示 + 咨询”，避免引入无必要电商复杂度。

**状态**：暂不实施。

### O-006 后台 CMS 范围

**问题**：院校、资讯、课程、导师、案例都可能发生变化，但一次性建设大而全 CMS 成本高。

**方向**：V1 先把后台做好学员课堂维护；只有被证明需要高频运营修改的数据，再逐步纳入后台。

**状态**：按需扩展。

### O-007 学员阶段趋势

**问题**：长期使用后，只看当前规划可能无法体现成长变化。

**方向**：未来可考虑绩点、英语成绩、科研/竞赛进展等阶段趋势，但避免为了图表而图表。

**状态**：V1 非阻塞。
