# V1 产品基线

本文件记录截至 2026-09-17 已由需求方确认的 V1 产品约束。后续若发生变更，应修改本文件并在提交说明中写明原因。

## 1. 原型权威程度

AIFORCE 提供的九辰保研小程序原型为 V1 高权威需求基线。

- 第一版原则上照原型开发；
- 允许指出明显缺陷和大幅优化空间；
- 未经确认，不擅自改变原型已经明确的页面、流程和字段；
- 优化建议与 V1 实现分轨管理。

## 2. 小程序主体结构

当前原型的五个主入口：

- 首页
- 定位
- 学堂
- 资讯
- 我的

V1 不是官网简单镜像，而是九辰保研数字服务平台的微信客户端。

## 3. AI 保研评估

V1 直接实现 AI 评估，不采用原型中固定五维权重规则作为核心逻辑。

### 目标

用户提交结构化背景信息后，系统结合院校/项目信息与真实保研案例，由 AI Agent 输出结构化分析结果。

### 原则

- 不使用机械的固定百分比评分作为主要决策逻辑；
- 不允许模型无证据生成精确录取概率；
- 评估结果需要可解释；
- 允许在资料不足时明确表达不确定性；
- AI 模型调用必须位于服务端。

### 评估额度

- 新用户可获得一定免费评估次数，具体数量以最终产品配置为准；
- 免费额度用尽后，可通过微信支付购买评估次数/额度；
- 课程不通过小程序在线购买。

## 4. 数据来源

九辰目前没有自有真实保研案例数据，但存在其他来源的真实保研案例数据。

要求：

- 数据必须保留来源属性；
- 非九辰服务产生的案例，不得宣传为九辰成功案例；
- 涉及个人信息的案例必须脱敏；
- 本地 XLSX/CSV 可作为整理与导入源；
- 线上数据库是生产系统唯一真实状态源。

## 5. 课程

V1 中课程模块只负责：

- 课程展示；
- 课程介绍；
- 在线咨询/联系顾问。

V1 不实现：

- 课程在线支付；
- 课程订单自动开通；
- 拼团、优惠券等电商能力。

## 6. “我的课堂”

V1 按原型提供的初步模型实现，不扩展成完整 LMS。

### 时间轴与展示规则

#### 大一至大三正常学期

展示：

- 绩点规划
- 英语规划
- 竞赛规划
- 科研规划

#### 大三暑假前的所有假期

仅展示：

- 英语规划
- 竞赛规划

#### 大四阶段

只展示：

- 实习规划

#### 大四寒假

只展示：

- 实习规划

### 绩点规划

- 导入学生每学期课程；
- 根据保研目标和课程难度，为每门课程设置目标分数；
- 辅导老师可点击查看老师介绍；
- 辅导记录由后台管理录入。

### 其他规划表

英语、竞赛、科研等规划表总体沿用原型“大一上”板块所展示的交互与信息逻辑。

### 实习规划例外

实习规划表需要删除：

- 辅导老师；
- 辅导/辅导记录相关内容。

## 7. 管理后台

V1 开发范围包含九辰内部管理后台。

当前最明确的后台职责是：

- 公司员工查找学员；
- 按阶段维护“我的课堂”数据；
- 更新绩点、英语、竞赛、科研、实习等规划；
- 录入辅导记录；
- 维护与课堂相关的必要导师信息。

院校、资讯、课程、案例等是否全部纳入后台 CMS，按实际维护频率逐步扩展，不在 P0 阶段强行做大而全后台。

## 8. 微信平台

九辰已具备微信小程序 AppID / 企业主体，微信公众平台开发侧已经准备，可进入后续开发、真机调试和版本上传流程。

敏感凭据不进入 Git 仓库。

## 9. V1 当前未冻结事项

以下事项需要在进入对应工程阶段前确认，但不阻塞 P0/P1：

- AI 模型供应商及模型选择；
- Agent 提示词、检索策略与结构化输出 Schema；
- 微信支付商户能力及具体充值档位；
- 数据库最终部署方式；
- 管理后台员工账号和权限粒度；
- 本地数据文档的标准字段模板。


## 10. 登录、身份与用户协议

小程序 V1 明确区分两个登录入口：

- 学员登录；
- 老师登录。

入口选择只表示用户希望进入哪一侧产品，不得由前端直接授予角色权限。

### 身份授权原则

- 微信身份统一映射到 `User`；
- 普通新用户首次登录默认仍为 `user`，可进入学员侧资料完善流程，但不自动获得签约学员数据权限；
- 正式学员由九辰后台将 `User` 与 `Student` 绑定，并赋予 `student` 角色；
- 老师必须由九辰后台预先创建/绑定 `Teacher` 档案并赋予 `teacher` 角色；
- 选择“老师登录”不能自动成为老师；
- 老师只能访问通过老师—学员分配关系授权给自己的学员数据；
- `staff/admin` 是内部管理身份，不与普通辅导老师概念混用。

### 用户协议

登录页必须提供用户协议勾选。

当前开发阶段允许使用占位协议正文，但系统从第一版即记录：

- 协议类型；
- 协议版本；
- 同意时间；
- 对应用户。

正式上线前必须替换占位协议文本与版本号。

### 会话

微信身份用于首次认证，API 后续访问使用服务端签发的随机会话令牌。权限判断必须在服务端完成，不依赖前端传入的角色或 userId。

## 11. 用户资料收集

用户自行填写的学业背景与签约学员业务档案分开管理。

第一阶段资料采集至少包含：

- 本科院校；
- 专业；
- 当前年级；
- 绩点 / 均分；
- 专业排名。

原则：

- 仅在业务明确需要时增加字段；
- AI 定位、“我的资料”等页面复用同一份本人资料，不重复建立多套事实源；
- 签约后的 `Student` 仍是九辰服务学员档案，不与普通用户自填资料强行合并；
- 涉及真实个人信息的生产数据不得进入 Git。
