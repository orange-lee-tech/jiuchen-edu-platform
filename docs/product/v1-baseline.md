# V1 产品基线

本文件记录截至 2026-09-17 已由需求方确认的 V1 产品约束。后续若发生变更，应修改本文件并在提交说明中写明原因。

## 1. 原型权威程度

AIFORCE 提供的九辰保研小程序原型为 V1 高权威需求基线。

- 第一版原则上照原型开发；
- 允许指出明显缺陷和大幅优化空间；
- 未经确认，不擅自改变原型已经明确的页面、流程和字段；
- 优化建议与 V1 实现分轨管理。

## 2. 小程序主体结构

当前原型的五个主入口：

- 首页
- 定位
- 学堂
- 资讯
- 我的

V1 不是官网简单镜像，而是九辰保研数字服务平台的微信客户端。

## 3. AI 保研评估

V1 直接实现 AI 评估，不采用原型中固定五维权重规则作为核心逻辑。

### 目标

用户提交结构化背景信息后，系统结合院校/项目信息与真实保研案例，由 AI Agent 输出结构化分析结果。

### 原则

- 不使用机械的固定百分比评分作为主要决策逻辑；
- 不允许模型无证据生成精确录取概率；
- 评估结果需要可解释；
- 允许在资料不足时明确表达不确定性；
- AI 模型调用必须位于服务端。

### 评估额度

- 新用户可获得一定免费评估次数，具体数量以最终产品配置为准；
- 免费额度用尽后，可通过微信支付购买评估次数/额度；
- 课程不通过小程序在线购买。

## 4. 数据来源

九辰目前没有自有真实保研案例数据，但存在其他来源的真实保研案例数据。

要求：

- 数据必须保留来源属性；
- 非九辰服务产生的案例，不得宣传为九辰成功案例；
- 涉及个人信息的案例必须脱敏；
- 本地 XLSX/CSV 可作为整理与导入源；
- 线上数据库是生产系统唯一真实状态源。

## 5. 课程

V1 中课程模块只负责：

- 课程展示；
- 课程介绍；
- 在线咨询/联系顾问。

V1 不实现：

- 课程在线支付；
- 课程订单自动开通；
- 拼团、优惠券等电商能力。

## 6. “我的课堂”

V1 按原型提供的初步模型实现，不扩展成完整 LMS。

### 时间轴与展示规则

#### 大一至大三正常学期

展示：

- 绩点规划
- 英语规划
- 竞赛规划
- 科研规划

#### 大三暑假前的所有假期

仅展示：

- 英语规划
- 竞赛规划

#### 大四阶段

只展示：

- 实习规划

#### 大四寒假

只展示：

- 实习规划

### 绩点规划

- 导入学生每学期课程；
- 根据保研目标和课程难度，为每门课程设置目标分数；
- 辅导老师可点击查看老师介绍；
- 辅导记录由后台管理录入。

### 其他规划表

英语、竞赛、科研等规划表总体沿用原型“大一上”板块所展示的交互与信息逻辑。

### 实习规划例外

实习规划表需要删除：

- 辅导老师；
- 辅导/辅导记录相关内容。

## 7. 管理后台

V1 开发范围包含九辰内部管理后台。

当前最明确的后台职责是：

- 公司员工查找学员；
- 按阶段维护“我的课堂”数据；
- 更新绩点、英语、竞赛、科研、实习等规划；
- 录入辅导记录；
- 维护与课堂相关的必要导师信息。

院校、资讯、课程、案例等是否全部纳入后台 CMS，按实际维护频率逐步扩展，不在 P0 阶段强行做大而全后台。

## 8. 微信平台

九辰已具备微信小程序 AppID / 企业主体，微信公众平台开发侧已经准备，可进入后续开发、真机调试和版本上传流程。

敏感凭据不进入 Git 仓库。

## 9. V1 当前未冻结事项

以下事项需要在进入对应工程阶段前确认，但不阻塞 P0/P1：

- AI 模型供应商及模型选择；
- Agent 提示词、检索策略与结构化输出 Schema；
- 微信支付商户能力及具体充值档位；
- 数据库最终部署方式；
- 管理后台员工账号和权限粒度；
- 本地数据文档的标准字段模板。


## 10. 登录、身份与用户协议

V1 使用统一登录入口，不再在登录页区分“学员登录 / 老师登录”。

### 登录方式

- 微信登录：当前真实可用；
- 账号密码登录：保留入口，待完整认证与找回密码机制接入后启用；
- 手机号登录：保留入口，待真实短信/手机号认证能力接入后启用；
- 禁止用假验证码或明文密码实现伪登录。

### 自动注册与游客

- 用户第一次通过可用认证方式登录时，系统自动创建 `User`；
- 数据库内部生成不可见 UUID，用于协议、会话与数据关联；
- 新用户不自动获得九辰业务身份，默认角色为 `user`，用户界面显示为“游客”；
- 游客可以访问公开内容与允许的基础能力，但不能访问老师、学员或管理员专属数据。

### 九辰内部ID

- 九辰内部ID是业务身份，不等于数据库 UUID；
- 学员、老师、管理员分别使用不同前缀的内部ID；
- 学员与老师可在“我的 → 个人资料”填写九辰提供的内部ID进行一次性认领；
- 填写内容与系统可认领ID不匹配时，显示“填写错误，请核对重新填写”；
- 认领成功后内部ID锁定，用户不能自行修改；
- 需要更换身份或解绑时只能由管理员操作；
- 管理员ID禁止通过个人资料自助认领，必须由已有管理员或本地内部后台完成绑定；
- 登录界面不让用户选择角色，系统根据数据库中已绑定内部ID自动展示游客 / 学员 / 老师 / 管理员对应界面。

### 用户协议与会话

- 登录页必须提供用户协议勾选；
- 当前开发阶段允许使用占位协议正文，但系统记录协议类型、版本、同意时间与对应用户；
- 微信身份用于首次认证，API 后续访问使用服务端签发的随机会话令牌；
- 权限判断必须在服务端完成，不依赖前端传入的角色或 userId。

### 退出与注销

- 退出登录只撤销当前会话，不改变业务身份与业务数据；
- 注销账号撤销全部会话、解除当前登录凭据、清理用户自填资料；
- 注销不得由用户自行删除九辰内部 Student / Teacher 业务档案；
- 已绑定内部ID在账号注销后进入禁用状态，由管理员后续处理；
- 业务档案、辅导记录等公司业务数据与用户登录账号生命周期分离。

## 11. 用户资料收集

用户自行填写的学业背景与签约学员业务档案分开管理。

第一阶段资料采集至少包含：

- 本科院校；
- 专业；
- 当前年级；
- 绩点 / 均分；
- 专业排名。

原则：

- 仅在业务明确需要时增加字段；
- AI 定位、“我的资料”等页面复用同一份本人资料，不重复建立多套事实源；
- 签约后的 `Student` 仍是九辰服务学员档案，不与普通用户自填资料强行合并；
- 涉及真实个人信息的生产数据不得进入 Git。

## 12. 手机管理员工作台

管理员在小程序“我的”中拥有独立管理工作台，首批覆盖：

- 创建、绑定、解绑、禁用或删除内部业务ID；
- 查看游客 / 学员 / 老师 / 管理员账号状态；
- 新增或移除老师—学员分配关系；
- 触发九辰教育微信服务号动态同步。

完整课堂编辑、批量数据维护等复杂操作继续保留在电脑端内部后台。

## 13. 动态 / 资讯同步

V1 优先同步九辰教育微信服务号已发布内容，不要求运营人员在小程序重复人工发布。

- 服务号 AppID / AppSecret 仅保存在服务端环境变量；
- 同步通过微信官方发布能力接口实现；
- 小程序数据库保存标题、摘要、封面、原文链接、发布时间与来源标识；
- 若服务号当前账号无对应接口权限，则保留手工录入作为后备路径，不采用非官方抓取作为默认生产方案。
