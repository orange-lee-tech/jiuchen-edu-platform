## 数据与筛选真实性
- 原有 39 所 985 与额外 77 条 211/校区名录记录保留，原始 116 历史工程记录不得统计成 116 个独立法人院校。
- 三所特色非211：华东政法大学（上海）、西南政法大学（重庆）、西北政法大学（西安），各校来源见 `apps/miniprogram/miniprogram/packages/schools/data.ts` 的特设源和官网。
- 全库目前 119 条；`五院四系` = 9 所、`国防七子` = 7 所。点击圈层时清理既有 985/211 等层次选项；地区/搜索仍允许用户主动缩小结果（上方提示匹配数量）。
- 不向用户呈现“985 · 39”等计数型筛选按钮；结果数量可独立展示。
- 这些标签是行业称谓，不是官方排名，不直接支持当年推免项目判断。

## 客服交接
- 按钮「咨询目标院校」使用现有 `openWechatCustomerService`，不额外创建收费客服服务。
- 点击后 `wx.showActionSheet` 可只咨询学校，或请求读取本人姓名、年级、专业。
- 客户信息仅从当前账号会话 + `/me/profile` + 当前绑定学员的 `/me/classroom` 读取；不跨学员，不用开放查询 ID。用户确认全文后复制到剪贴板并打开微信客服，需要**用户亲自在聊天窗口粘贴并发送**。
- 当前微信客服 `wx.openCustomerServiceChat` 不提供安全可靠的自动填充/发送任意文本参数，不得承诺自动发消息。退出/取消即不复制。

## 课表 BLOCKER 和生产
- 用户新实测报错 `HTTP 400 / invalid_schedule_edit_payload`，证实旧完整版课表 PUT 无法接收当前识别出的课程格式。日期选择问题与生产接口不兼容问题是**两个独立 bug**。
- 代码已新增专用 `/me/classroom/schedule-imports/:id/term-start-date`，仅带日期，对原课表 JSON 做 `JSON_SET`，并从数据库回读确认；客户端在旧 API 返回路由不存在时会回退旧接口一次，可能再次触发 400，必须正确报错。
- **解除 BLOCKER 的必要条件是新 API release 经审批部署到 ECS**；不能只更新手机端。此时 `p1/foundation` 还有支付、AI 上下文等未正式生产放行的新功能，严禁未经分流 B gate 整分支上线；需挑出日期 PUT 所需最小源码、测试、生产 schema 只读验证和回滚窗口。
- 真机观察：点击选周一→服务端 200→关闭页面重开→原周一仍在→本周课表匹配正确。任何一步 FAIL 都不能宣布完成。
