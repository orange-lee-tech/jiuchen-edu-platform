# 原型实现说明

原型来源：`https://4m1v2d1nnfyp2.aiforce.cloud/app/app_17e305xjk37`

本文件不是重新设计需求，而是记录开发时如何解释原型，以及哪些地方已有额外确认。

## 1. 原型定位

该原型是 V1 的高权威产品基线，不只是视觉参考。

开发顺序应优先保证：

1. 信息架构一致；
2. 核心操作路径可用；
3. 数据状态真实；
4. 视觉还原合理；
5. 再考虑非必要的细节优化。

## 2. 五个主入口

- 首页
- 定位
- 学堂
- 资讯
- 我的

其中“定位”和“我的课堂”是业务复杂度最高的两个区域，不能只按静态页面实现。

## 3. AI 定位

原型中的固定五维评分/权重展示不作为 V1 核心规则，应删除或改造为 AI 结构化分析结果。

保留的核心体验：

- 用户填写背景资料；
- 选择/查看目标院校；
- 获得 AI 分析；
- 查看推荐理由、风险与相似案例；
- 保存历史评估；
- 免费额度用尽后购买评估次数。

## 4. 学堂

学堂需明确区分两类能力：

- **课程介绍**：面向潜在客户，展示课程并引导咨询；
- **我的课堂**：面向签约学员，展示长期培养规划和辅导信息。

不要把两者混成同一套购买/学习系统。

## 5. 我的课堂

原型“大一上”可作为规划表交互和信息层级的主要示例，但时间轴本身必须数据驱动，不复制多套同类页面。

特别注意：

- 绩点规划需要课程级目标分数；
- 导师介绍可从规划入口进入；
- 辅导记录来自后台录入；
- 实习规划不显示导师和辅导记录；
- 不在 V1 自行扩展作业提交、直播、聊天、审批等 LMS 功能。

## 6. 课程与支付

原型中的课程价格信息可用于展示，但 V1 不做课程在线购买。

唯一支付闭环：

`AI 评估额度不足 -> 微信支付充值 -> 服务端确认 -> 增加评估次数/额度`

面向用户的文案优先使用“评估次数”“评估额度”，内部技术实现可以使用 credit/token 概念。

## 7. 数据与案例

原型中的案例、院校、项目等展示数据不能默认视为九辰自有经营数据。

开发期应：

- 使用脱敏/演示数据；
- 给案例保留来源字段；
- 给可公开状态留出字段；
- 避免在 UI 中自动拼接“九辰成功案例”等未经确认的营销表述。

## 8. 实现优先级

对于原型中尚未形成闭环的边缘功能，优先做页面与基本交互，不在 V1 自动扩展业务复杂度。任何明显值得优化之处，记录到 `optimization-backlog.md`。


## 9. 2026-09-20 九辰提供的 HTML 原型源码

九辰另提供了一份单文件 HTML/CSS/JavaScript 可交互原型源码。

使用优先级：
- 用于核对页面结构、字段密度、交互路径：高参考价值；
- 用于核对产品覆盖面：高参考价值；
- 用于复制生产数据模型、AI 算法、支付、权限：禁止直接照搬。

已观察到该原型为了演示而使用：
- 前端固定 AI 画像/院校要求/权重；
- 前端变量模拟评估次数和充值；
- JavaScript 常量保存课堂计划、辅导记录、课程、院校等大量业务数据；
- 单页面隐藏/显示方式模拟页面导航。

这些都是合理的原型技术，但不是 Production 架构。
