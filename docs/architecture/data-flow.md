# 数据流与关键业务流

## 1. 本地数据导入

```text
九辰整理 XLSX / CSV
        ↓
后台上传或开发期导入工具
        ↓
字段映射 + Schema 校验
        ↓
错误报告 / 人工修正
        ↓
正式数据库
        ↓
小程序 / 后台 / AI 统一读取
```

原则：文档是输入材料，数据库是线上真相源。

## 2. “我的课堂”维护

```text
公司员工登录后台
        ↓
查找学员
        ↓
选择培养阶段
        ↓
维护该阶段允许出现的规划类型
        ↓
录入目标 / 课程分数目标 / 导师 / 辅导记录
        ↓
服务端权限与数据校验
        ↓
数据库
        ↓
学员小程序读取并展示
```

规划类型由阶段规则限制，避免后台录入一个前端不应展示的规划。

## 3. AI 保研评估

```text
用户填写结构化背景
        ↓
API 校验并标准化输入
        ↓
检查免费/付费评估额度
        ↓
检索院校、项目、真实案例
        ↓
构建 Agent 上下文
        ↓
调用 AI 模型
        ↓
结构化输出 Schema 校验
        ↓
保存评估记录
        ↓
成功后记账扣减额度
        ↓
小程序展示结果
```

重要约束：

- 不在小程序直接调用 AI 模型；
- 不让模型直接修改额度或数据库业务状态；
- AI 失败时不应无故消耗额度；
- 输出必须经过服务端 Schema 校验。

## 4. 评估额度充值

```text
用户选择充值档位
        ↓
API 创建内部订单
        ↓
服务端调用微信支付
        ↓
小程序发起支付
        ↓
微信支付结果
        ↓
微信服务端回调 API
        ↓
验签 + 金额/订单校验 + 幂等
        ↓
Payment 标记成功
        ↓
CreditLedger 增加额度
        ↓
用户看到新的可用评估次数
```

小程序前端的“支付成功”回调不能作为增加额度的唯一依据。

## 5. 小程序发布与服务器部署

两条链路独立：

### 小程序代码

```text
本地开发
  -> 微信开发者工具预览/真机调试
  -> 上传微信版本
  -> 体验版/审核版
  -> 正式发布
```

### API/数据库

```text
本地开发
  -> staging 测试环境
  -> 真机联调
  -> production 正式环境
```

因此开发过程不是“所有东西做完 -> 一次性上传服务器”。基础 API 能跑通后，应尽早建立 staging 环境，后续逐步联调微信真实能力。
