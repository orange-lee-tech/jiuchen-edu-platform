# P1 基础骨架验收标准

P1 的目标不是完成业务页面，而是证明三端与数据层能够以最简单方式稳定工作。

## P1 完成条件

1. 微信开发者工具可以正常导入 `apps/miniprogram`，并显示基础页面；
2. `services/api` 可以本地启动，`GET /health` 返回稳定的结构化结果；
3. `apps/admin` 可以本地启动，并显示九辰管理后台基础壳；
4. API 接入 Test MySQL，并完成第一条 Migration；
5. 小程序可以在真机 Test 环境访问 API；
6. 完成最小微信用户身份链路，服务端能够把微信身份映射到业务用户；
7. 后台能够读取一个虚构/脱敏测试学员；
8. Secret、真实学生数据和本地私有配置均不进入 Git。

## 当前施工状态

截至 2026-09-17，代码侧已经完成：

- 小程序、管理后台、API 三个最小工程骨架；
- GitHub CI 对小程序 TypeScript、后台构建、API 类型检查/测试/构建进行验证；
- API 数据库连接层、Drizzle Schema、演示学员 Seed 和学员读取接口；
- 管理后台与小程序的 API/演示学员读取链路；
- 微信 `wx.login` 客户端引导和服务端 `jscode2session` 身份映射骨架；
- CloudBase 云托管用 API 容器文件；
- Test 环境接入清单。

剩余项均依赖真实 Test 基础设施或微信开发者环境：

- 真实小程序 AppID；
- CloudBase Test 环境；
- Test MySQL；
- 云托管部署后的 API 地址；
- 微信开发者工具 / 真机联调。

## 明确不属于 P1

- 不还原完整 AIFORCE UI；
- 不开发完整“我的课堂”；
- 不接 AI 模型；
- 不接微信支付；
- 不做复杂权限系统；
- 不建立复杂 CI/CD 平台。

## 通过原则

P1 只有一个判断标准：**最小闭环是否真实可运行**。如果为了满足某个工具或框架而新增的复杂度不能改善这个闭环，就不加入。
