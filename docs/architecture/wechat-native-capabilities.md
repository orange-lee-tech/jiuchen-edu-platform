# 微信官方能力优先清单

> 更新时间：2026-09-20  
> 原则：能由微信小程序/公众平台官方能力完成的基础平台问题，优先使用官方能力；只有官方能力不满足业务要求时才自建替代方案。

## 1. 当前必须采用的官方能力

| 业务 | 官方能力 | 我们的用法 | 状态 |
|---|---|---|---|
| 微信一键登录 | `wx.login` + 服务端 `code2Session` | 获得微信身份，建立 User 与服务端 Session | 已实现，待集中验收 |
| 本机号码登录 | `button open-type="getPhoneNumber"` + 服务端手机号换取接口 | 用户主动授权，后端换取手机号；不自建短信验证码 | 施工中 |
| 服务号资讯 | access_token + 发布能力 `freepublish/batchget` | 同步九辰教育服务号已发布文章 | 官方链路已验证 |
| 微信支付 | 小程序支付官方接口 + 服务端回调 | 仅购买 AI 评估额度 | P5 |
| 用户隐私 | 微信小程序隐私授权/隐私保护指引相关能力 | 正式上线前接入并审查收集字段 | P6 |
| 分享 | 小程序分享能力 | 院校/资讯/评估结果在合规范围内分享 | 按页面需要 |
| 客服/咨询 | 微信官方客服、拨打电话等能力 | 优先承接课程咨询，减少自造聊天系统 | 待业务确认 |
| 文件 | `wx.downloadFile` / `wx.openDocument` / `wx.uploadFile` | 课程资料、简历等需要时使用 | 按模块施工 |
| 更新 | `wx.getUpdateManager` | 正式版更新提示和重启 | P6 |
| 网络状态 | `wx.getNetworkType` / 网络状态监听 | 必要时区分网络故障和业务故障 | P6 |
| 自动化测试 | 微信开发者工具 CLI/HTTP + `miniprogram-automator` | 页面导航、点击、输入、断言、回归自动化 | 后续接入 |
| 真机验证 | 微信开发者工具真机调试 | OpenID、手机号授权、支付等真实微信能力验收 | 集中测试窗口 |

## 2. 登录原则

V1 登录页只保留：

1. **微信一键登录**
   - 小程序调用 `wx.login`；
   - 服务端调用微信登录凭证校验接口；
   - 服务端建立自己的 UserSession。

2. **本机号码登录**
   - 使用微信手机号快速验证组件；
   - 用户主动点击并授权；
   - 前端只把一次性手机号 code 交给服务端；
   - 服务端调用微信官方手机号接口；
   - 不让客户端自行声称某手机号已验证。

手机号快速验证属于微信平台单独授权能力，正式上线前必须在小程序后台确认当前主体资格、调用额度与收费规则。该能力不可用、用户拒绝或额度异常时，不得影响“微信一键登录”继续使用。

V1 不提供：
- 用户名/密码；
- 自建密码找回；
- 手输手机号 + 自建短信验证码登录；
- 假验证码；
- 仅由前端决定身份的伪登录。

## 3. 账号与业务身份仍然分离

微信身份/手机号只解决“你是谁”。

九辰内部ID解决“你在九辰业务里是什么身份”。

因此：

```text
微信登录 / 手机号快速验证
          ↓
        User
          ↓
   默认游客（role=user）
          ↓
九辰内部ID认领/管理员绑定
          ↓
Student / Teacher / Admin
```

手机号和微信登录都不能直接把普通用户升级为学员、老师或管理员。

## 4. 官方能力使用规则

每进入一个微信相关模块，施工前先做：

1. 查微信开放文档是否已有官方组件/API；
2. 确认主体、认证、基础库、权限、额度等前置条件；
3. 优先做最小官方链路验证；
4. AppSecret、支付密钥等只放服务端；
5. 对官方接口错误码做明确诊断；
6. 官方能力不可用时，再讨论自建 fallback；
7. 不用爬虫、模拟点击或非官方协议替代已有官方 API。

## 5. 不等于“全部依赖微信”

官方能力优先主要针对：
- 身份；
- 手机号验证；
- 支付；
- 服务号；
- 分享；
- 客服；
- 隐私；
- 小程序生命周期等平台能力。

九辰自己的核心业务仍由我们负责：
- 内部ID；
- 学员档案；
- 师生授权；
- 我的课堂；
- 案例库；
- AI 评估；
- 额度账本；
- 管理后台。

也就是说：**平台能力不重复造轮子，业务能力仍保持自主可控。**


## 6. 测试也优先使用微信官方工具链

后续集中测试拆成两层：

### 可自动化回归
优先使用微信开发者工具自动化能力：
- 页面打开；
- Tab/子页面导航；
- 元素存在性；
- 表单交互；
- 普通 API mock / fallback；
- 登录前后的页面状态；
- 课堂、资讯、个人中心的非真实身份回归。

### 必须真实微信身份的验收
保留人工/真机：
- 不同 OpenID 的账号隔离；
- 手机号授权；
- 多个真实账号的 Student / Teacher / Admin 权限；
- 微信支付；
- 正式体验版平台行为。

目标不是消灭真机测试，而是把多人、多设备资源只用在官方平台确实要求真实身份的测试点上。
