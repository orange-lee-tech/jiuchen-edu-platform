# 系统架构总览

## 1. 目标

九辰教育平台 V1 采用“一个微信小程序 + 一个内部管理后台 + 一个 API 服务 + 一个正式数据库”的简单架构。

目标不是追求复杂技术栈，而是保证：

- 微信端稳定、易用；
- 公司员工能维护学员数据；
- AI 评估和支付逻辑位于可信服务端；
- 数据可追溯、可迁移、可维护；
- 后续需求增长时仍有清晰扩展路径。

## 2. 逻辑架构

```text
                    ┌──────────────────┐
                    │    微信小程序      │
                    │ 用户 / 学员使用    │
                    └─────────┬────────┘
                              │ HTTPS
                              ▼
┌──────────────────┐   ┌──────────────────────┐
│   九辰管理后台     │──▶│       API 服务        │
│   公司员工使用     │   │                      │
└──────────────────┘   │ Auth / Student       │
                       │ Classroom / Content   │
                       │ AI / Credit / Payment │
                       └──────┬─────────┬──────┘
                              │         │
                        ┌─────▼────┐ ┌──▼──────────┐
                        │  SQL DB   │ │ AI 模型服务   │
                        └──────────┘ └─────────────┘
```

## 3. 前端

### 微信小程序

首选：

- 原生微信小程序；
- TypeScript；
- TDesign Miniprogram；
- 微信开发者工具作为官方开发/上传入口。

不采用 Taro/uni-app 作为 V1 默认方案，因为当前产品目标明确为微信小程序，没有跨平台收益足以抵消额外抽象成本。

### 内部管理后台

首选：

- Vue 3；
- TypeScript；
- Vite；
- TDesign Vue Next。

后台第一目标是高效维护学员课堂数据，不追求展示型 Dashboard。

## 4. API

API 采用 Node.js + TypeScript 的轻量单体服务。

建议模块边界：

- `auth`：微信用户、后台员工认证与权限；
- `students`：学员档案；
- `classroom`：阶段、规划、课程目标、辅导记录；
- `content`：院校、案例、课程、资讯等逐步纳入；
- `assessment`：AI 保研评估；
- `credits`：评估额度与流水；
- `payments`：微信支付下单、回调与幂等；
- `imports`：XLSX/CSV 数据导入与校验。

V1 不拆成微服务。

## 5. 数据库

生产数据库是线上业务唯一真实状态源。

本地 XLSX/CSV 的定位：

- 原始数据整理；
- 批量导入；
- 人工审阅；
- 必要时的离线备份。

不得让微信小程序直接读取本地文档，也不得把 Git 仓库里的 JSON 当生产数据库。

## 6. AI 层

AI 调用统一放在服务端。

建议流程：

```text
学生结构化资料
  -> 输入标准化
  -> 检索院校/项目/案例
  -> AI Agent
  -> 结构化 JSON 输出
  -> Schema 校验
  -> 保存评估记录
  -> 返回小程序
```

AI 模型供应商通过适配层隔离，避免核心业务绑定某一家 API。

## 7. 微信平台与服务器的关系

微信小程序代码本身不是传统网站那种“上传到自己的服务器后运行”。

- 小程序前端：通过微信开发者工具本地开发、预览、生成体验版并上传版本到微信公众平台；
- API/数据库：部署在我们自己的测试/生产服务器或云服务；
- 小程序通过 HTTPS 调用 API；
- 微信公众平台配置合法域名、权限及后续支付等能力。

因此不会等所有功能完成后再第一次部署服务器。P1 基础链路完成后应尽早建立测试环境，用于真机验证微信登录、网络域名、权限和后续支付链路。

## 8. 环境

至少区分：

- `local`：开发者本机；
- `staging`：测试/真机联调环境；
- `production`：正式环境。

生产环境数据和凭据不得用于普通本地开发。
