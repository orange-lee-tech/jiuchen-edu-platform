## 已施工的代码

1. 虚拟支付原先仅靠小程序调用对账。新增服务端每分钟限量扫描、按订单年龄退避的查询补偿；仅微信官方订单查询核对金额、单号、交易号后通过现有幂等账本入账。已支付但未确认发货者在重启后继续补发。新增 `payment_orders.virtual_reconcile_checked_at`、`virtual_delivery_confirmed_at` 两列迁移；老订单金额和次数不改。付款后离开页面不再依赖客户端完成入账。超过七天仍未确认的订单需要人工对账，不会被自动判作付款失败。退款仍需财务核对，不能自动抵销已消费额度。
2. 新增 `admin_control_boxes`、`admin_control_audit` 和各管理员隔离的 `admin_control_drafts` 三表。已有管理员身份上叠加两个各自加盐 scrypt 的六位 PIN：`settings` 管价格与免费规则，`assessment_key` 管 AI Key。两盒分别首次设定后成为全局生效版本；任何已登录管理员持对应盒的现 PIN 可提交新内容与新 PIN（允许相同），更新全局版本并留下审计。连续五次错码锁定十五分钟。没有旧 PIN 时可单独保存只归当前管理员的草稿，**草稿不得影响价格、额度、模型密钥或支付**；取得正确旧 PIN 与新 PIN 后按草稿所依据的现行版本启用，版本已变化则先重新保存草稿。密钥草稿和生效密钥都以服务器配置的独立 32 字节主密钥用 AES-256-GCM 加密，任何接口不返回原始 Key；缺主密钥时写入拒绝。旧版“仅首次录入者可更换密钥”规则已取消。
3. 管理员页面可调单次和十次人民币价格、游客与学员赠送数，须填人工核实的单次模型成本；勾选微信商品价格核实时要求两档每次售价至少覆盖估计成本并留 20% 缓冲。改价取消旧确认，未再次确认前不开放新下单。此估算不代表真实利润；供应商余额与实际 token 成本仍无自动读数。
4. 设置版本只用于**以后首次领取相应阶段免费额度的账户**；账本中已领游客和学员升级额度不会因为改版本再次领取。旧余额保留，订单创建时金额与次数不可改。生产 `CREDIT_ENFORCEMENT_ENABLED`、虚拟支付密钥与批准开关仍由部署权限控制，后台不能绕过。
5. 后台 AI Key 更新后评估运行时按次从加密盒取最新密钥；未初始化盒时保留现有环境配置。其他管理员的受控连接测试会发一次极短模型请求，可能产生费用。管理页还展示账户加入天数、学员与老师建档时间；老师建档时间**不等于实际雇佣起始日期**，后者需要业务方另行确认来源。

## 验证及尚欠真实验收

- 本地 API TypeScript/build 与 **224/224** 测试 PASS；小程序 TypeScript 与 **64/64** 导航交互测试 PASS。测试运行环境是 Node 24，ECS 的 Node 22 和资源限额仍须在固定提交后独立复验。
- 需在生产备份可恢复点已核对后，先在生产结构副本演练两个新迁移，再单独审批生产 DDL：`npm run db:upgrade:virtual-delivery`、`npm run db:upgrade:admin-controls`。现有 `db:upgrade:credit-payment` 已在 10 月 18 日生产执行，不重复。
- 生产密钥主密钥、微信商品价格、模型成本和资金状态不能写入 GitHub/Actions/聊天。主密钥需要独立加密备份与恢复演练；丢失将无法解密后台录入的 API Key，六位 PIN 不能代替主密钥。负责人账号失效的恢复需运营审批，不留隐藏超级管理员入口。
- 真实商户验收：生产迁移与固定 SHA 发布后，在微信商品后台核对两档价格和商品 ID；输入现有虚拟支付环境密钥并开启经过批准的开关；先做一笔最小金额真机实付，核订单查询、仅入账一次、退出页面后后台补偿、发货确认、评估完成扣一次、模型失败返还、周/月/年金额和次数；退款另核财务。未经现场实付不能记 PAYMENT PASS。
- AI 供应商余额没有可用的自动只读余额接口证据。当前 `AI_SUPPLIER_BALANCE_FEN` / 时间为人工读数，过期或缺失会在统计中标记，**不能承诺额度永不耗尽**。需要供应商官方余额/账单能力、运营补充资金责任人与告警渠道，才可验证抗断供目标。模型失败时已有返还机制，本次没有扩大评估额度开关。
- 微信 0.0.19 是上一固定前端；本次前端有新设置页，必须在固定新 SHA 上传**新的**体验版，按管理员两盒、其他角色禁止设置、真实充值和 AI 成功/失败路径做真机验收。旧体验版验证不能代替新候选。

## 发布原则

`main` 记录施工，不因代码合入而自动执行新生产 DDL、API 切流、支付开关或微信正式发布。各步骤按精确 SHA 和现场回执分开记账；备份最小恢复点在任何新 DDL 之前复核。当前两套 PIN 没有密钥所有者账号丢失后的网页自助恢复；由甲方运营授权的线下恢复流程处理。
