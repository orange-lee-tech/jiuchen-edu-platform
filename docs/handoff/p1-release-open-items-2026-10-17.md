# 小程序正式发布闭环：未完成项与建议顺序（2026-10-17）

本页供决定首发范围，不授予生产 DDL、切流、收费、微信发布权限。事实依据见 [CURRENT](CURRENT.md)、[候选验证](p1-release-closeout-2026-10-16.md)、[真机清单](p1-unified-device-acceptance-2026-10-14.md)。排序按业务价值；第7项虽放在最后讨论，凡触发生产数据库写入仍先满足可恢复点。

## 1. 冻结“首发”的含义和候选

当前可选的两个真实目标：

| 目标 | 首发承诺 | 必须先过的业务门槛 |
| --- | --- | --- |
| 核心免费正式版 | 登录、资料、课表、已有 AI 评估、院校、人工客服、明确范围内的旧资讯；收费入口关闭且说明未开放 | Profile 完善资料、固定候选无越界功能、真实角色/真机回归、ECS 真实负载与回滚 |
| 完整商业正式版 | 核心链路加 Token 充值、额度发放/扣减、真实金额统计，若承诺最新公众号和个人收藏还包括 News V2 | 上述全部，另加商业表与支付商户/回调、News 七表/开关/来源验收；具体法规与微信平台准入以账户审核为准 |

用户此前明确小程序核心要能收钱并统计次数，因此建议完整商业版作为正式交付目标；先判断最新服务号资讯和收藏是否同批硬承诺。免费核心版只作有限体验或明确过渡，不能代替正式收费验收。源码候选 e5908185 含 AI quality v3 且无独立开关；只批准核心时要剥离为新 SHA。不能把集成分支整树推生产。两种路径都可让已经验证的旧功能先通过有限体验版检查，但“体验版通过”不等于正式付费闭环。

## 2. Profile 资料写入是核心阻断

生产缺 user_profiles.enrollment_year，GET /me/profile 曾报 500。资料完善又是首次 AI 评估前置，故它比新报表或备份工具体验更靠近用户核心链路。临时 MySQL 的幂等迁移和旧行往返已过；生产真实结构与恢复门槛未过。

建议只审批单列可空变更，给出精确 DDL、受影响行/索引/字符集、执行前恢复点、失败回退与读写验证。不要把 News 七表或支付表混进 Profile 的审批。列存在且真实学员资料保存/重开真机通过后，才记此项完成。

## 3. 收费和次数：决定是否阻断首发

用户确认的学员总计免费5次（游客1次、升学员另加4次）、单次¥1.90/十次¥16.90 已写入固定 e590 服务端策略，449 前端也有虚拟支付充值和核实订单入口；e590 与现役 8cc4 的商业源码无差异。至少三张生产表缺失，第四张 payment_notifications 待只读确认；生产付款、赠送、扣减均未验收，充值金额不能算0。CREDIT_ENFORCEMENT_ENABLED 默认关闭；旧 JSAPI 下单端点恒返回503。

完整商业首发需稳定的赠送版本、确认游客资格、退款与争议处理、官方虚拟支付商户准入、商业四表精确变更、真实支付查询/重复入账/失败返还及财务对账，再做不同账号真机试付。旧 JSAPI 回调代码不是虚拟支付的上线证据；详见[独立审查包](p1-paid-release-scope-and-schema-review-2026-10-17.md)。保持 AI 评估已有持久化链路且不改模型/Prompt/RAG。若先发免费核心版，关闭充值及额度强制执行的可见入口，维护文档注明商业未交付；这是一种明确缩小范围的上线决定，不把付费链路假装通过。

## 4. 资讯“有内容”与“自动抓全”要分开

旧 /news 路由可用；10月12日目标服务号文章已发表却不在已扫描 freepublish 两页40组41篇中，因此不能宣称自动同步覆盖最新内容。News V2 的正常30条、超窗旧文72小时、个人收藏与退役任务已有合同和临时关系 Gate；生产七表缺失、开关未启用。独立视频能否由官方来源枚举也未证实。

若首发必须展示最新公众号文章：先用官方可核实原链接的受控补录建立真实样本，同时诚实标“应急补录”；要个人收藏/30＋72，则另过七表 DDL、API、开关和真机 Gate。自动来源需找到服务号实际接口可证的文章 ID/URL，不能拿补录冒充自动同步。若首发先保留旧资讯，明确其范围和更新局限，不把“30条与72小时”写进上线承诺。支付、Profile 与资讯来源调查可并行，资讯七表 DDL 仍受备份前置约束。

## 5. 管理端、老师与手机体验

已有真实学员课表、评估与172张院校图片的历史真机 PASS。新前端固定点通过类型检查/95项回归，但新首页、资料、老师/管理员四栏、身份/统计、客服复制后手动发送、报告普通图/长图/水印及 Markdown/Word/PDF 实际打开还需真机。支付来源缺表应显示不可用。部分已分配学员/老师真实样本尚缺，按 DATA PENDING 记录。

建议用固定前端和明确匹配的 API 能力上传一次体验版，按统一清单集中验收，失败只修对应模块。跨身份只读镜像不是普通管理员查看权限的自然延伸，需要独立批准和负例；若首发不承诺，避免把这项样本缺口拖住基础四栏发布。coaching/growth 表缺失的页面必须核对实际路由；首发承诺则补结构与验收，未承诺则从正式可用清单中移出，不做假数据页面。

## 6. 受控部署、资源与正式提审

后继 API 的类型检查/215测试/构建与 News/Profile 临时库 Gates 已过。ECS Node22 编译、256MiB/50%CPU/64任务的无库冒烟已过；新候选尚未在真实 DB/AI 负载与持续并发下证实资源余量。生产 active 最后核到8cc4，不能把 staging 目录当上线。

范围冻结后生成精确候选和文件清单；获得各项生产 DDL/程序/开关的独立审批，复测真实负载，按既有 approved-release/READY/promote 自动健康与回退切流。随后跑角色/付款（若承诺）/资讯（若承诺）真机清单，版本一致才提交微信审核和正式发布；证据以实际审核与发布记录为准。

## 7. 备份与恢复：业务排序末位，生产写入前置

10月16日 doctor 所查已知官网与 API 源站、目录和SQLite都为 true。管理员本地加密组件备份的前六项已下载，但整代 PARTIAL；10月17日 db-check 完成 WSL 本机 MySQL8 检测、ECS 配置读取和 SSH 隧道建立，MySQL_CONNECT_AND_ENGINE_CHECK 返回 MYSQL_ERROR_2026。该码在官方 MySQL 中是客户端 SSL 连接错误；只凭数字不能断定具体证书/协议/网络原因。数据库 SQL 未导出，隔离恢复、跨资产完整性、生产覆盖均未完成，productionBackupRestored=false，fullBusinessCoverage=false。

建议将增量/区间封存、三代轮换、官网/小程序/共享入口选择性生产覆盖与演练作为后续运维建设；先解决最小生产库可恢复点，才能执行 Profile/News/商业等 DDL。区间 JSON 不是可靠恢复的替代品，用户旧数据和删除/更新事件不能因分块而遗失。当前不自动降低 TLS 要求，也不重跑整套组件。工具详见 [说明](../../tools/maintenance/README.md)与[合同](../ops/business-backup-restore-contract-2026-10-16.md)。

## 我建议的决定

我建议以完整商业版为正式交付目标，支付和真实回调属于同批阻断；可先上传有限体验版验证不依赖新表的旧链路。若用户另行决定先发布免费过渡版，必须在版本承诺中明确收费未交付。最新自动资讯若是硬要求，来源缺口也升为同批阻断。无论选哪条路径，Profile 真资料、准确候选范围、真实负载/真机与实际微信审核不能跳。备份功能迭代排最后，生产数据库写入前的最小恢复证据仍排在相应 DDL 的前一关。
