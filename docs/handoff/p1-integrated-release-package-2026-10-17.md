## 一次性体验版会话

前提：完成相应**独立**生产门槛后固定 API/前端 SHA 和微信体验版版本，确认实际后端 active SHA、表 checker 与开关。对目前缺少门槛的项填 BLOCKED，继续其他可执行项；不反复上传碰运气。体验版上传和正式提审是不同操作。

| 顺序 | 当场角色与操作 | 可核实结果/失败记录 |
| --- | --- | --- |
| 1 公众号及客服 | 管理员核后台原文与接口差异，核实补录（若 V2 已合法启用），学员打开文章；游客/学员/老师/管理员分别发起客服，确认→复制→手动粘贴发送 | 两篇近期真实文章的 URL/标题/时间、原文可打开；补录来源说明正确；客服侧实际收到对应身份。无补录/接口时注明来源 BLOCKED，旧文章照实验 |
| 2 学员 | 新账号和旧学员逐一浏览首页→规划→机会→我的，完善资料，第一周/本周课表，评估草稿/历史/导出 | Tab 始终四项；资料保存重开；课表真实；客服及报告不漏个人数据。Profile 缺列不能填 PASS |
| 3 老师/员工 | 实际分配账号四栏、所属学员规划与审核、未分配空态；非所属目标负例 | 仅获授权学员可读写；无样本写 DATA PENDING，不制造分配 |
| 4 管理员 | 四栏、用户/分配/资讯，周/月/年评估统计；普通用户试管理员路由负例 | 角色一致；评估成功9条全历史与具体区间分开；商业来源缺表显示不可用而非零。跨身份只读仅在扩权获批且负例通过后计入首发 |
| 5 商业 | 如商户准入、表/开关获批：游客与学员赠送、取消、小额成功、延迟和重复核实、失败释放/扣次、退款与管理页金额 | 服务端可信查询入账一次，真实订单与账本及统计一致；未开启不作模拟通过 |
| 6 回归与发布 | ECS 固定限额真实 DB/AI/并发；按既有发布器观察健康和回退，最后微信正式提审 | OOM/restart/健康/业务样本有回执；官网不受影响；审核及版本发布记录在微信平台可查 |

统一回填：步骤、北京时间、手机型号/系统/微信版本、前端 Git SHA、API active SHA、体验版版本、PASS/FAIL/BLOCKED/DATA PENDING、HTTP/错误码、脱敏证据位置。真名、session、密钥、支付凭据、私人报告及截图不进 Git/聊天。

## 施工次序与授权边界

1. 本轮先做公众号受控入口与来源修正、角色和商业跨模块审计；前端以新 SHA 跑 typecheck/导航/资讯回归。现役和固定候选证据不回填新 SHA。
2. 生产最小可恢复点与相关结构隔离演练一旦通过，分别申请 Profile 单列、News 七表、商业四表。备份系统的长期区间化和三代轮换排在业务最后；数据库写入前的最小恢复门槛不能后移。
3. API e590 含 AI quality v3、跨身份只读和 News V2；这些与程序切流/开关各自要范围确认。付款需官方商户准入及回调查询/发货/退款契约，不以源码“有接口”放行。
4. 人员、商户和手机一次会话按上表集中验收。缺样本写 DATA PENDING；缺商户/生产表写 BLOCKED；发布前统一复核，不把无 DB 冒烟或代码测试称为真机通过。
