## A. 目标与事实

设计参考是用户的四屏效果图，**不是可直接作为静态页面使用的成品**。前一次 B1/B2 被用户判为视觉 FAIL：不能再靠给原卡片换四种背景色交差。本轮应一次施工四个一级页面，不再按 B2→B3→B4→B5 等待逐页批准；由用户自己做人眼、真机验收，Codex 只做代码与定向测试。

已核实源码：`apps/miniprogram/miniprogram/pages/{index,classroom,news,profile}/`；四个 Tab 仍为「今天 / 规划 / 机会 / 我的」。对应新本机倒数日逻辑位于 `pages/index/index.ts`，曾存在面板在入口下方、点击后没有自动进入视口的问题；总控已在基线提交中加入打开时滚动到面板的最小修复，仍需本地和真机复验。

现有三份视觉文档（施工计划、验收细目表、微底色规范）与独立 ZIP 是设计参考，全部以本蓝图为落地范围。现有 ZIP 的横幅是**扁平插画**，目标效果图的校园照片氛围更强；插画不能自动实现照片效果。如需照片，只能使用已获授权的真实图片或另行经用户批准的资产，不得冒充真实学校和不明来源照片。

## B. 绝对保护边界

1. 不重写已完成的账号登录、身份、规划/老师直接保存、AI 评估、计次、支付、收藏、资讯、学校、客服、管理员等业务。既有 WXML 事件、TS handler、路径、权限、接口及异常状态必须保留。
2. 仅改四个一级页面的 WXML/WXSS/必要展示 TS、必要共用视觉资源，以及与学期同步相关的最小独立 domain/API 代码和定向测试。避免新依赖与数据库迁移。
3. 严禁把效果图中的课程、进度 2/4、剩余次数、具体学期、已分配老师、考试报名状态、头像、通知数量写死进代码。
4. 禁止覆盖本地已有未提交的 `apps/miniprogram/project.config.json`、`docs/handoff/CURRENT.md`、两份 UI 矩阵、`.release-staging/`、`ops/ecs/`、`tools/maintenance/` 等资产。无 `git clean/reset --hard`，不使用 `git add -A`。
5. `main`、ECS、腾讯云生产数据、微信正式发布均不改。允许在现有 UI 分支完成普通提交与推送，前提是用户本地没有新增冲突；不强推。
6. 不要求 Codex 获取开发者工具截图、真人扫码、模拟器效果图；由用户验视觉。代码收口只做一次必要定向测试。

## C. 共同视觉规格：高保真而非四色后台

- 手机内容宽度使用安全区；左右边距 24–28rpx，栏目间距 14–20rpx，主标题 30–36rpx，正文 24–27rpx，次级 20–23rpx。
- 色板：蓝 `#174E78`；交互蓝 `#2A6B92`；金 `#CEA460` 少量；纸灰背景 `#F6F4F0`；白 `#FFFEFC`；课表 `#E7F1F7`；规划 `#F7ECDE`；常用入口 `#E8F2EC`。
- 真实手机上的**信息层级**比区块颜色更重要。应引入含裁切控制的轻量品牌横幅、真实列表密度、图标对齐、主操作优先、空/错状态和适度留白。
- 卡片不应堆叠五层边框、顶金线和大阴影。可用 12–18rpx 圆角；整体同源但四页不复制同一种卡片墙。
- 素材 ZIP 的可选原名：`banners/today-campus-hero.webp`、`banners/semester-books-banner.webp`、`banners/school-library-hero.webp`、`banners/profile-calm-campus.webp`；图标有 `calendar`、`ai-assessment`、`library`、`news`、`clock`、`headset`、`english`、`trophy`、`flask`、`profile` 等 WebP。仅加入实际使用的资源，已有的今天横幅/图标不再重复拷贝。
- 横幅高度约 175–245rpx，须留出标题动态叠加空间；不使用单张大图片替代交互组件。小程序静态资源路径全部核对大小写与实际文件存在性。

## D. 四页一次施工，明确验收目标

### D1 今天（index）：一屏像真正的工作台

1. 顶部从“单调纯蓝空盒”改为有真实视觉主体的精简品牌区域：真实日期/可用学业信息在左、插画/真实授权图片在右，避免“今天”重复三次、营销口号和无功能小字。
2. 课表是第一主模块。保留今天/明天开关与完整课表入口；真实课程时采用时间、课程名、教室/下一节的紧凑时间轴；无课表、休假、无课、读取失败严格区分。
3. 规划是第二主模块。保持真实四类计划和状态，允许进入规划；不假造“今日任务完成数”。
4. 入口区采用视觉母版里的**紧凑图标矩阵**：AI 评估、院校库、保研资讯、倒数日；联系客服必须明显可达，不能误删。倒数日入口需有可触达的新建/删除/日期选择 UI，显示“本机保存”而非云同步；检查弹层/面板能自动进入视口。
5. 低频品牌入口放最下方，避免首屏堆满服务宣传。

### D2 规划（classroom）：把老侧栏彻底变成学期工作流

1. 页首学期横幅采用书本素材或等效授权图；当前浏览阶段可选、真实档案当前阶段独立显示。已有折叠学期选择器必须保留，不恢复旧常驻纵向侧栏。
2. 课程成绩、英语、竞赛、科研／实习四类计划做成带图标、主状态、直接进入操作的紧凑列表；学期与假期计划类型由现有 `stage.planTypes` 决定，不可画出不允许的编辑入口。
3. 主辅导老师、协助关系、辅导记录保留原始授权语义，不能显示虚构的老师姓名或已完成次数。保留课表导入、编辑、保存失败与回读路径。
4. 老“待审核后生效”文案不得恢复；学生本人/已授权老师直接保存正式计划是当前有效规则。

### D3 机会（news）：真正的资讯流

1. 顶部紧凑搜索/分类（如已有真实可用功能；无搜索后端不可添加假搜索）；院校库是有品牌视觉的主入口，校园插画仅做通用品牌装饰，不冒称真实院校。
2. 分类/时间/来源清楚，资讯列表采用高密度横向缩略图 + 标题/发布日期/来源，最多两三行正文，不做重复大封面全屏堆叠。
3. 收藏、退出缓存/历史文章移到次级区域，不删除数据；现有收藏、服务号原文、站内详情、返回和账号切换隔离保留。
4. 没有可靠时效字段就不能给“即将截止/进行中”假标记；媒体图片失败要有回退，不造成布局跳动。

### D4 我的（profile）：个人空间而不是编号管理页

1. 轻量个人横幅，真实用户名/身份动态呈现；没有合规头像数据就使用一致的中性图标/默认形状，不用效果图假人物。
2. 编号保留查看与复制，降级为紧凑次要区，不在首屏重复大展示。成长档案、AI 评估、收藏、客服/真实老师入口明显。
3. 退出/注销与身份绑定/切换保留原事件及确认，放在低频设置区；免费账号与老师/管理员兼任身份使用相同权限与状态判断。
4. 收藏卡片新布局不得恢复导致标题挤成竖行的缺陷。

## E. 当前学期/入学年份：需要解决真实数据不一致

已核实后端存在两个不同来源：
- `user_profiles.enrollment_year`：用户填写的入学年份；`GET/PUT /me/profile` 可读写。
- `students.current_stage`：原学堂/规划读取的当前学期；例如沿用 `freshman-fall`，与年份不会自动同步。

所以“不该锁在大一”判断成立，但**不能直接仅改一个 label**，否则规划和课表仍会按旧阶段读取。

施工要求：
1. 独立实现可测试的四年制本科**建议阶段推导**：按中国学年（通常九月起新学年），10 月的学期应为 fall；春/寒暑假按已有 `STAGE_DEFINITIONS` 和明确日期规则映射，不用浏览器时区推导学校具体校历。
2. 对缺失、未来入学年、超过四年、转专业/休学/学制非四年、未知或人工特殊阶段返回“待确认”，不可偷偷写大一。
3. 计划页与今天页应该读取一致的**有效当前阶段**；如保留老字段，必须提供受鉴权的阶段同步/更正机制，并以服务端可复读为准。不允许仅前端改显示文字、实际写入/课表仍取大一。
4. 优先复用已有 `/me/profile`、学员关联与课程阶段代码；最小后端实现如需改接口，补入学年→阶段的边界单测、相关授权单测及直接保存/历史计划不混淆的回归。
5. 不在本轮触碰生产数据库或执行 DDL，不强制覆盖用户专门选择的学期/假期。学员显式确认更正或经验证的服务端规则优先。
6. 这个模块作为独立代码提交，不能和四页视觉混在同一大提交里；若 API 配套验收尚未完成，清楚标记新 UI 不应直接对线上旧 API 执行真实写入。

## F. 一次性交付规则

- Codex 同时完成 D1–D4 四页，不需逐页申请审美批准。由用户统一检查四页真实预览；Codex 不需做截图/二维码。
- 使用原本分支、原本目录。核对 HEAD 后先保护本地未提交资产；只对本轮真实改动显式 `git add`，按“共享视觉/四页布局/学期同步”分成少量有意义的提交，普通推送。
- 完成后运行一次小程序 `npm.cmd run typecheck`、`node --test tools/testing/miniprogram-navigation.test.cjs`、`git diff --check`；如改 API，额外运行 API typecheck、build 和涉及阶段的定向测试。不要循环跑全部 300 项，不生成大 ZIP、长日志、演示材料。
- 四页 WXML 必须通过事件/绑定/图片路径扫描；核对账号切换、导航路由、课表/规划当前阶段、异常提示与原有业务入口。
- 任何涉及支付、AI 次数、订单、密钥、老师授权、生产部署的代码都排除在本轮之外。
- 最终只汇报：基线、提交 SHA、模块完成状态、修改文件、资源大小、测试摘要、阻塞和真人验收待办。真实视觉未验时不能写 PASS。
